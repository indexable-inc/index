1. **BLOCKER — The boundary key omits evaluator settings.** Evidence: `maintainers/ix/boundary-memo.md:117-121` defines the key solely as `ident(args[0])`. `rust/nix-eval-rs/src/drvstrict.rs:391-405,465-475,665-669,752-871` reads `ca_derivations`, `blake3_hashes`, and `store_dir`. The existing whole-eval key includes the complete settings fingerprint because omitting `store_dir` previously served another store’s output path (`rust/nix-eval-rs/src/readset.rs:1409-1485`; `rust/nix-eval-rs/src/eval.rs:1380-1394,1601-1717`). Scenario: fill a row for `__contentAddressed = true` with CA derivations enabled, then look it up with the feature disabled. The proposed key and witnesses match, so replay serves a result where the body errors. With a `NoStore` host, even replaying the old `StoreText` question cannot detect a changed `store_dir`, because both answers are `NoStore`. Fix: include `Settings::fingerprint()`, the boundary kind, identity-schema version, and evaluator/builtin ABI version in every boundary key.

2. **BLOCKER — Serving omits required `Vm::drv_hashes` state.** Evidence: every normal `derivationStrict` branch inserts its modulo hash before returning (`rust/nix-eval-rs/src/drvstrict.rs:675-688,834-848,851-869`). The VM calls this map required in read-only mode (`rust/nix-eval-rs/src/vm.rs:570-586`). A downstream derivation consults it before attempting `DrvSource::read_drv` (`rust/nix-eval-rs/src/drvpath.rs:560-581`), while `InProcess` always refuses that read (`rust/nix-eval-rs/src/drvstrict.rs:977-1003`). The proposed payload and serve path contain only result attrs, questions, and emissions (`maintainers/ix/boundary-memo.md:171-173,195-199`). Scenario: child derivation A is served into a fresh process, then B consumes `A.out`. B cannot find A’s modulo hash and becomes `Unimplemented`; a cold run succeeds. Replaying `WriteDrv` does not repair the in-memory map. Fix: store the canonical `DrvHash` in the payload and insert `(drvPath, DrvHash)` before returning every served result, including recursively verified sub-boundaries.

3. **BLOCKER — Foreign closures and builtins are unobserved.** Evidence: witnesses record only foreign slots “holding data” (`maintainers/ix/boundary-memo.md:143-155`), but application dispatches foreign closures, builtins, and `__functor` sets (`rust/nix-eval-rs/src/vm.rs:1743-1884`). Scenario: force `f = if readFile flag == "a" then (x: "a") else (x: "b")` before entering the boundary, then use `f null` in a derivation attribute. The world read is outside the extent, both closures are units in the same unchanged module, and the root construction identity remains the same. Applying `f` reads no foreign data leaf, so the old witness validates and serves the wrong derivation. Fix: record a typed observation for every foreign non-data value used: closure `(module, unit, env identity)`, builtin index plus partial arguments, callable-set identity, and PendingApply structure.

4. **BLOCKER — Foreign failures are observable but absent from witnesses.** Evidence: slots can hold `Failed(Catchable)` (`rust/nix-eval-rs/src/value2.rs:1168-1172`); forcing rethrows it (`rust/nix-eval-rs/src/vm.rs:1715-1718`), and `tryEval` converts a catchable throw into data (`rust/nix-eval-rs/src/task.rs:923-935`; `rust/nix-eval-rs/src/primops_pure.rs:841-858`). Scenario: pre-force `x = if pathExists flag then 1 else throw "boom"` through an outer `tryEval`, then use `(tryEval x).success` inside `derivationStrict`. The recorded run sees a foreign `Failed` slot and produces false; the current run sees a foreign `Value(1)` and should produce true. No data observation was recorded for the old failure, so the old result can be served. Fix: witness every foreign terminal outcome, including typed `Failed` data and `Unimplemented` token/detail. Treat `Blackhole` as uncacheable.

5. **BLOCKER — The only specified scalar digest drops string context.** Evidence: construction identity for data is `H(kind, bytes)` (`maintainers/ix/boundary-memo.md:62-65,93-94`), while `NixStr` stores bytes and context separately (`rust/nix-eval-rs/src/value2.rs:943-949`). `derivationStrict` folds context into `inputSrcs` and `inputDrvs` (`rust/nix-eval-rs/src/drvstrict.rs:710-735,933-941`). Scenario: pre-force either `"${./dep}"` or `unsafeDiscardStringContext "${./dep}"` outside the boundary. The bytes are identical, but one derivation depends on the store object and the other does not. A bytes-only digest accepts the stale witness. The proposal leaves the foreign-leaf digest otherwise undefined, so the proof has no sound digest definition. Fix: define value digests over type, exact scalar representation, and canonical sorted `ContextElem` variants. Do not reuse `NixStr` equality, which deliberately ignores context (`rust/nix-eval-rs/src/value2.rs:1079-1086`).

6. **BLOCKER — The proposed tag propagation cannot record paths through the actual boundary body.** Evidence: the proposal tags operand-stack operations (`maintainers/ix/boundary-memo.md:161-169`), but `bi_derivation_strict` directly iterates `Attrs`, clones child slots, and yields raw forces (`rust/nix-eval-rs/src/drvstrict.rs:188-203,250-359,429-455,573-584`). Tasks carry raw `Slot`s and `Yield`s without provenance (`rust/nix-eval-rs/src/task.rs:790-918`; `rust/nix-eval-rs/src/vm.rs:1934-1965`). `attrValues` similarly returns a new list containing source slots directly (`rust/nix-eval-rs/src/primops_pure.rs:1436-1445`). Scenario: `args` is produced by `attrValues foreignSet`; an already-forced foreign element changes. Its route crosses direct Rust iterators and task state, never a tagged `StackEntry`, so no navigable observation is produced. Fix: make provenance a companion of every slot/value in task work items and every `Yield::{Force,Apply,Sub}`; centralise `Select`/`Index` propagation. Any unprovenanced read must make the boundary uncacheable.

7. **BLOCKER — `ShapeOf(names)` is not an exhaustive observation model.** Evidence: formal matching reads membership, defaults, and unexpected keys directly (`rust/nix-eval-rs/src/vm.rs:1764-1837`); set/list equality observes lengths and keys (`rust/nix-eval-rs/src/task.rs:1193-1232`); `toJSON` probes `__toString`/`outPath` and walks containers directly (`rust/nix-eval-rs/src/deepwalk.rs:325-397`); `functionArgs` returns whether each formal has a default, not just its name (`rust/nix-eval-rs/src/primops_pure.rs:2724-2756`). `unsafeGetAttrPos` observes source origin, line, and column (`rust/nix-eval-rs/src/primops_pure.rs:1668-1704`), an input explicitly required by Decisions 2 and 3 (`../../doc/nix-incremental-eval/design.md:452-466,641-690`). Scenario: two foreign closures have identical formal names but different defaults; the proposed shape digest is identical while `functionArgs` changes the derivation. Fix: define typed observations such as `AttrsNames`, `ListLen`, `Membership(name)`, `FormalSchema(name, has_default)`, and `AttrPosition(name)`. Route all container and origin inspection through tracked APIs; raw `Attrs` dereferencing cannot remain an unchecked path.

8. **BLOCKER — Persisting `Select(sym)` can navigate to another attribute.** Evidence: `Sym` is explicitly local to one VM (`rust/nix-eval-rs/src/value2.rs:12-13`), assigned in interning order (`rust/nix-eval-rs/src/vm.rs:1096-1108`), and the VM documents that memoisation and sibling scheduling can change that order (`rust/nix-eval-rs/src/vm.rs:217-243`; `rust/nix-eval-rs/src/eval.rs:637-641`). The persisted path syntax uses `Select(sym)` (`maintainers/ix/boundary-memo.md:143-148`). Scenario: numeric symbol 7 meant `builder` while recording and means `decoy` during replay. If `decoy` has the recorded digest, replay accepts it while the real `builder` changed. Module hashes do not detect interner ordering. Fix: persist attribute-name bytes and intern them in the current VM during replay. Shape digests must likewise hash names, never global symbol numbers.

9. **BLOCKER — One recorder scope stack cannot represent sibling fibers or causal order.** Evidence: fibers are parked whole while siblings run (`rust/nix-eval-rs/src/vm.rs:196-243,1190-1212,1261-1275`). Slow questions retain only their `Question` until collection (`rust/nix-eval-rs/src/readset.rs:976-996,1335-1356`), and the scheduler spawns siblings after beginning one (`rust/nix-eval-rs/src/eval.rs:618-635,785-801`). The proposal supplies one scope stack (`maintainers/ix/boundary-memo.md:123-142`). Scenario: boundary B begins `Realise` and parks; sibling C enters another boundary and asks synchronously; B’s answer is then collected while C is current. A global push/pop either assigns B’s answer to C or loses it. The same reordering can place a later attribute’s replay force before the earlier question that would reject the witness; replay can then diverge in work the sequential body would never reach. Fix: store extent lineage on each `Fiber`, attach it to resume tokens and tickets at ask time, and keep a globally sequenced event tape with causal child references. A stack on `RecordingHost` is insufficient.

10. **BLOCKER — Evaluated boundary questions can disappear from the existing whole-evaluation memo.** Evidence: the design says boundary exit pops its questions into its own witness, but only a served boundary splices questions into the parent (`maintainers/ix/boundary-memo.md:137-142`). The whole-eval cache records only `recorder.take()` after the run (`rust/nix-eval-rs/src/session.rs:164-181`), and the code explicitly treats omitting one evaluation’s directory read as a wrong memo answer (`rust/nix-eval-rs/src/eval.rs:566-574`). Scenario: the initial evaluation executes a boundary containing `readFile`; its question is removed from the root log. After the file changes, the whole-eval lookup hits before any boundary lookup occurs and serves the old top-level result. Fix: tee every question to the root and all enclosing extents, or splice executed children as well as served children. Avoid double-recording when replay calls `Question::ask` through a `RecordingHost`.

11. **BLOCKER — Replay mutates the real heap and cannot safely convert errors to misses.** Evidence: `advance_force` first replaces the slot with `Blackhole` (`rust/nix-eval-rs/src/vm.rs:1674-1679`). On a root-fiber `Unimplemented`, unwind deliberately writes nothing back (`rust/nix-eval-rs/src/vm.rs:1590-1619`) because today the evaluation terminates. The proposal instead catches replay refusal and continues with a miss (`maintainers/ix/boundary-memo.md:201-204`). A subsequent body force finds an ownerless blackhole and reports infinite recursion (`rust/nix-eval-rs/src/vm.rs:1695-1700`). Restoring only the initiating slot is insufficient because nested forces have also memoised values or failures. Fix: perform each witness attempt in an isolated copy-on-write VM/heap transaction and discard it wholesale on miss. Without isolation, navigation must never execute arbitrary thunks.

12. **BLOCKER — Replay can duplicate, reorder, or leak emissions and host effects.** Evidence: `RecordingHost` records and immediately forwards warnings and traces (`rust/nix-eval-rs/src/readset.rs:948-975,1249-1273`). Navigation performs real evaluation, then a hit replays the stored emissions (`maintainers/ix/boundary-memo.md:184-198`). Scenario: a thunk traces `T` before reading its foreign leaf. Navigation emits `T`, validates, and the payload emits `T` again. On a failed candidate, `T` can escape even though the real body stops at an earlier error. Store operations performed by speculative navigation cannot be rolled back either. Per-boundary emission vectors also cannot reproduce an interleaving such as B1, sibling C, B2. Fix: isolate heap and host effects per attempt, buffer all emissions, discard validation output, and replay the payload once on a hit. Boundaries that perform non-transactional host effects must be uncacheable.

13. **MAJOR — Existing verification can certify the same bad boundary row.** Evidence: a sampled whole-eval hit re-evaluates and compares (`rust/nix-eval-rs/src/session.rs:221-253,274-300`), but its only special mode is a quiet recorder (`rust/nix-eval-rs/src/session.rs:164-174`; `rust/nix-eval-rs/src/readset.rs:1011-1022`). Quiet mode does not bypass memo lookup. Scenario: the “fresh” arm serves the same incorrect boundary result as the whole row being checked; the values agree and `hits_checked` rises while `hits_disagreed` remains zero. Fix: propagate `MemoMode::BypassAll` through every fiber during whole-eval verification. A boundary verifier must likewise bypass its own key, use tri-colour recursion state for sub-boundary cycles, and compare result, error class/position, emissions, and side-state.

14. **MAJOR — Construction identity and `forced_by` are not total lifetime-safe definitions.** Evidence: the identity table omits concrete VM constructors such as `MkList`, `ConcatLists`, `MkAttrsOnto`, and `Update` (`rust/nix-eval-rs/src/vm.rs:2475-2603`), although these produce the same `Value::List/Attrs` types (`rust/nix-eval-rs/src/value2.rs:15-31`). `repoint_thunk` can also reuse a non-Thunk slot unchanged (`rust/nix-eval-rs/src/vm.rs:3220-3227`). Meanwhile `forced_by` is only a `u32` “index of the boundary” with no non-reuse rule (`maintainers/ix/boundary-memo.md:128-132`). Scenario: if sequential extents reuse a stack index, B reads a slot forced by earlier A and mistakes it for B-owned work, omitting its witness. A monotonic `u32` wraps after about 58,000 evaluations at 73,520 boundaries per evaluation. Fix: enumerate a construction recipe for every aggregate-producing operation and make missing recipes a compile error. Use a non-reused VM/evaluation epoch plus a 64-bit extent ID stored on each fiber, never stack depth or a recycled vector index.

15. **MAJOR — The 10%/25% line is not credible from the stated cost model.** Evidence: the proposal leaves all allocation and operation counts blank while globally widening slots, frames, sets, and lists (`maintainers/ix/boundary-memo.md:244-268`). Its claimed current layout is already inconsistent with the source: `NixStr` alone contains a fat `Rc<[u8]>` plus a context pointer (`rust/nix-eval-rs/src/value2.rs:945-949`), while `SlotState::PendingApply` contains a `Slot` plus `Vec<Slot>` (`rust/nix-eval-rs/src/value2.rs:1185-1188`). The model omits tagged `StackEntry`s, task provenance, parallel frame vectors, persistent paths, module sets, and allocator size-class changes. Against 67.2s, 10% is 6.72s; touching all 61.8M `y.Force` events leaves 109ns each before the 5.4M Apply events and 27.9M Done events. Against 12.1GB RSS, 25% is 3.025GB, but no peak-live object count exists. This directly reverses Decision 2’s “per-thunk anything is out” conclusion (`../../doc/nix-incremental-eval/design.md:369-405,846-850`). Fix: require static layout assertions, allocator-rounded size measurements, peak-live counters, and paired feature-on/off stages before accepting the architecture. As written, both thresholds are aspirations rather than supported estimates.

16. **MAJOR — The acceptance gate can pass without a useful warm-edit win, while replay retains the dominant boundary cardinality.** Evidence: `derivationStrict` builds a full ATerm/reference request (`rust/nix-eval-rs/src/drvstrict.rs:883-900`); `RecordingHost` clones it into replayable `StoreText` (`rust/nix-eval-rs/src/readset.rs:1156-1183`), and replay calls the store again (`rust/nix-eval-rs/src/readset.rs:658-664`). The supplied 73,520 `WriteDrv` calls closely track cpp’s 67,698 `derivationStrict` calls, so they reflect nixpkgs structure and remain on the hit path. The 32.4s aggregate question time has no per-kind breakdown. The document sets only cold overhead limits, with no required warm-edit wall time (`maintainers/ix/boundary-memo.md:266-269,301-313`). Fix: add per-question timing and bytes, candidate/path counts, cache I/O, maximum witness bytes, and a preregistered warm-edit target against both feature-off Rust and the 33.6s cpp baseline. Deduplicate StoreText blobs across whole and boundary witnesses.

17. **MAJOR — A materially simpler sound design already exists, and the proposal has become a second evaluator.** Evidence: completing findings 3–12 requires provenance through every VM op, task, builtin, container observation, scheduler event, error, and side effect. Decision 1 already recommends a persistent evaluator or COW zygote specifically because pointer identity removes cross-process identity and replay (`../../doc/nix-incremental-eval/design.md:269-337`). A smaller cross-process cache can instead key after `DrvStrict::finish` has produced canonical derivation inputs/ATerm (`rust/nix-eval-rs/src/drvstrict.rs:698-900`); that design is sound but does not skip forcing. Fix: choose explicitly between that modest post-force cache and the persistent evaluator/zygote for early cutoff. Replay-by-navigation should not proceed until it demonstrates a smaller trusted surface than the evaluator it shadows.

The proposal should be blocked. Its current key can cross settings, a hit omits required VM state, and the witness model misses observable values, errors, contexts, shapes, and positions. Replay also mutates the live heap and cannot preserve fiber-scoped effects. Fixing those issues requires pervasive provenance and transactional evaluation, which defeats the stated cold-cost premise. The 10%/25% thresholds are not credible without measurements, and there is no quantitative warm-edit success criterion.
